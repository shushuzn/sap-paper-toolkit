# academic-paper-improvement 论文改进

当任务是"评审/改进/润色一篇中文学术论文"或用户指出论文存在格式、引用、论证、语言问题时使用。

本 skill 只做一件事：**把改进意见落到可追溯的真实要求上，并逐处改到能核对。**

本 skill 不含任何具体稿件、机构、课程、人员与年份的信息。所有依据以任务方提供的原件为准，层内不带可定位到具体对象的标识。

---

## 零、六条硬性禁令（先于一切要求，无条件执行）

以下六条不属"建议"，也不因评分标准未写而失效。**违反即交付失败**，不得以"标准没写""风格偏好"为由豁免。历次返工均因违反这几条而起。

| 编号 | 禁令 | 判定 | 违反实例 |
|---|---|---|---|
| **禁令 1** | 正文、摘要、图表题注、注释中**不得出现**：课程、课程论文、本课程、课件、讲义、课堂、教材、结课、学时、课后 | 全文与 docx（含表格单元格）机械扫描，命中即 FAIL | 在正文里写"某课件所列的产品型号""本文为课程论文" |
| **禁令 2** | **不得使用破折号「——」**。需解释、列举、转折时，改用冒号、分号、逗号或另起一句 | 扫描 `——`，命中即 FAIL。单字线「—」仅限连接号（如"结构—性能"），不在禁令内 | 一处改动里新增两个"——" |
| **禁令 3** | **不得用脚本批量替换改正文**（`str.replace` 全量、`sed -i`、正则 `sub` 全局）。必须逐字读原句，一次只改一句，一处一个改动 | 改动前须有原文摘录；提交信息不得出现"批量替换" | 用全局替换清禁词，致指代落空 |
| **禁令 4** | **教学材料不得作为数据来源或引用来源**：讲稿、课件、讲义、课堂板书、教学视频、校内习题与答案，一律不得为稿件提供数值、曲线、案例或参考文献条目。**数据必须回到公开文献、标准或可核验的原始出处** | 稿件中每个数字须能指认公开出处；文献表中出现教学材料类条目即 FAIL（脚本 `R7`）；来源仅为教学材料者，删除或改定性 | 把教学材料里的用量与倍数写进正文，还顺手换了单位口径 |
| **禁令 5** | **不得用 `git add -A` / `git add .` 提交**。提交前先 `git status --short` 逐行看，只 `git add <明确路径>`。目检渲染件、`*.bak_*` 草稿备份、被否的教学材料，一律不入库 | 提交前须给出待提交文件清单；仓库须带 `.gitignore` 与 `pre-commit` 拦截（见 `references/repo-hygiene.md`） | 一次全量暂存带入数十个文件，含课件、校验件与备份 |
| **禁令 6** | **不得使用对偶否定句式**：不是 A 而是 B、并非 A 而是 B、不在 A 而在 B、不在 A 而是 B、不在于 A 而在于 B、不是 A，是 B、与其说 A 不如说 B、A 而非 B、而不是 B。要否定就直接给否定判断，要立论就直接给肯定命题，不借"先否后立"的对举撑句子 | 按九种形态扫描稿件，命中即 FAIL（脚本 `F7`）；引述他人原文、标准条文或用户原话时须加引号并标明来源，不得成为自述句式 | 摘要用对举句下判断，正文同句照写 |

**禁令的适用范围**：只约束稿件本身（正文、摘要、关键词、图表题注、注释、参考文献题名照抄除外）。本 skill 的规则文件必须原样列出这些词，否则无法界定禁令，故规则文件不扫、不算违规。核验脚本也只扫稿件路径。

**禁令 6 对规则文件同样生效**：本文件与 `references/` 的行文也要遵守，唯一的例外是列举禁用形态的地方（禁令表的"违反实例"列、执行规程里的示例），那里必须原样写出句式，否则无法界定禁令。

**禁令 1 的替代写法**：需要指代材料来源时，写"文献""公开报道"，或直接不写来源。**不得因删除禁词而编造出处**（见铁律 3）。禁令优先于句式通顺：宁可拆句、改主语，也不留禁词。

**禁令 2 的替代句式**：`A——B` → `A：B`（B 是解释）/ `A。B`（B 是独立判断）/ `A，B`（B 是补充）。改后须读一遍，不得出现"：："或"。，"这类拼接残留。

**禁令 3 的执行规程**：Read 取原文 → 在原文中定位到**一句** → Edit 只替换这一句 → 下一句重新 Read。改完必须给出「原文 → 改后」逐处对照表。**唯一例外**：构建脚本中的文献表、表体数据等非行文内容可按行处理，但须逐条断言定位。

**禁令 4 的执行规程**：教学材料只能用来理解概念、发现选题，不能进入稿件。遇到一个数字，先问三句：这个数字在公开文献里能找到吗；我手上的引注真的含有这个数字吗；还是它只出现在教学材料里。三条答不上来的，按下列顺序处理，**不得跳步**：

1. **回溯**：查到原始公开文献（正式出版物、期刊论文、标准原文），核实数值与单位口径，按 B 层著录规则补引注。
2. **降级**：回溯不到，但结论本身可靠时，删除具体数值，改为不含数字的定性表述，不留"某研究表明"这类无址顶替。
3. **删除**：降级后与前文重复、或该论断全靠这个数字支撑时，整句删除，并检查是否牵连摘要、引言、结论中的对应提法。

**禁止的三种"补救"**：把数字改挂到没核实过的文献上（伪造引注，比原来的错误更重）；把教学材料列进参考文献表（来源不合规）；改写数值或单位使"看起来像文献值"。这三条与禁令 4 同罪。

**禁令 5 的执行规程**：每次提交前固定三步，不许并成一步。

1. `git status --short` 通看一遍，逐行确认这个文件该不该进。
2. 只 `git add <明确路径>`，路径写到文件名，不用通配。交付件与源文件可以一次 add 多个，但要逐个列出。
3. 提交后 `git show --stat --oneline HEAD` 复核，文件数与预期一致才继续。

仓库缺 `.gitignore` 或 `pre-commit` 时，先补机制再提交；只清当次垃圾不改机制，下一轮必然复发。完整机制与可复制的配置见 `references/repo-hygiene.md`。

**禁令 6 的执行规程**：这类句式把两个判断压进一句，读者先要拆对举再还原命题；更常见的毛病是用对比掩盖论证不足，否掉一个弱选项并不等于立住了自己那个。改法按原句实际承担的职能选，三种：

1. **拆成两句**：`不是 A，而是 B` 改为 `B。A 在此不成立。`，B 先立，A 作补充否定。判断有把握时用。
2. **只留肯定**：`A 而非 B` 直接写 B，A 当作已排除项，不再回指。适用于 A 是显然错误选项。
3. **换成程度表述**：`决定项不是 A 而是 B` 改为 `B 是决定项，A 的权重低得多`。两句信息都要保留时用，可避免绝对化。

改后回读两条：不得出现两个否定连用造成的语气塌陷；不得为避开句式把否定信息整个删掉，该否的仍要否，只是不用对举。

违反任一条后的补救：撤回至备份，按禁令重做，不留"已改好"的中间态。

## 一、五条铁律

### 铁律 1　每条要求必须可追溯

改进意见只能来自三层依据，且必须写明层级与编号：

| 层级 | 内容 | 标注方式 |
|---|---|---|
| **A** | 任务方给出的评分标准或验收口径原文 | `A8`（见 `references/requirements.md`） |
| **S** | 机构格式文件（排版、结构、文献数量的强制来源） | `S2`（行距固定 20 磅） |
| **B** | 公开规范（著录、标点、数字、量和单位、编号等，编号向原文核对） | `B:著录`（只写维度，不写编号） |
| **C** | 学科惯例、本规则集已确认规则 | `C1` / `C2-5` |

**A 与 S 会冲突，处理规则**：A 层优先于 S 层；但 A 层若写"格式参照某文体"，即把 S 层引入为格式依据。S 层写的另一文体专属要求不得套用到本文。

追不到任何一层的，只能写为「**建议（非要求）**」并说明理由。**不得把个人偏好包装成规范**（字号、行距、页数、表格样式、标题用"1"还是"一、"均属偏好，见 C3）。

### 铁律 2　改动逐处可核对

- 改前备份原稿，改后给出「位置 / 原文 / 改文 / 依据 / 为什么必须改」五行对照。
- **禁令 3 的展开**：禁止全局字符串替换处理语义性指称。同一句话里"谁在说、数据源是什么"必须逐句判断，否则必然留下指代落空与伪归属（C2-4）。
- 不许以减少说明性内容换取字数达标（C2-11）。

### 铁律 3　宁删一句，不编一个出处

文献、数据、标准条文的核验规程见 `references/anti-fabrication.md`，未完成核验的内容不得写入稿件。重点：

- 不凭印象补卷期页码、不因"看起来像"推断文献内容、不把 DOI 尾号当文章号。
- 规范只引"编号 + 名称 + 要点"，不编条款号；"修订计划"不得写成现行限值。
- 推断只能写为推断，并给验证路径。
- **教学材料只算传递环节，够不上出处**，即便它给出的数值看起来权威。见禁令 4：回溯不到公开文献的，降级为定性或删除，不得改挂到未核实的文献上。

### 铁律 4　格式参照只参照排版参数，不参照文体身份

当任务方说"格式参照某文体"时，可照搬的只有纸张、页边距、行距、字号字体、标题层级、表格线型、公式编号、著录格式这一类**排版参数**。

不得照搬的是**身份要件**：封面、诚信声明、页眉中的机构名与文体名、目录、致谢、附录、指导教师与答辩信息、另一种文体的章节构成。把这些写进本文，读者会误认稿件类型，属冒用文体，比排版偏差严重。

判定方法：问"这一项是让页面更好看/更规范，还是在声明这篇稿件是什么"。前者可参照，后者一律不加。详见 `references/requirements.md` 的"S 层适用边界"。

### 铁律 5　论断强度不得超过证据强度

有出处不等于撑得住。同一个数字，看到了原文、只看到摘要里的量级、由公式算出、还是仅有机理推理，能支持的写法完全不同。**一个论断的可信度不可能高于其最弱一环的证据**，这是本规则最先于字句的地方。

证据分四级（工作定义，非学界术语，为本规则集可核对而设）：

| 等级 | 含义 | 判定 | 可支持的写法 |
|---|---|---|---|
| **E1 逐字** | 看到了原文（期刊全文、标准正文、专著页），数值、条件、单位逐字一致 | 能指出页码、表号、条款号 | "测定为""报道为""标准规定为"，可写精确值与区间端点 |
| **E2 量级** | 只看到摘要、图表、二次综述或检索摘要中的量级，未取到原文 | 能指出文献但指不出页 | "约""量级""数个数量级"，**不得写精确值与小数** |
| **E3 可复算** | 由本文公式或计量关系算出 | 给出算式或公式编号，他人可重算 | "按式（n）估算"，须附算式 |
| **E4 定性** | 仅有机理推理或普遍做法，无具体数据 | 指不出任何文献与算式 | "机理上应""通常""可以预期"，**不得出现具体数值** |

**匹配规则（硬性）**：论断的措辞强度不得超过其证据等级。

| 证据降级 | 必须同步做的删改 |
|---|---|
| E1 → E2 | 删精确值、删小数、删区间端点，改"约""量级"；不得保留"实测"字样 |
| E1/E2 → E3 | 删引注（已无文献支撑），补算式，改"估算" |
| E1/E2 → E4 | 删全部数值与"实测/报道"字样，改机理表述 |
| 任一降级 | **回扫三处**：摘要、引言、结论中同一论断的提法必须一并降级 |

**摘要与结论取全文最弱证据**：摘要写"经验规律"而正文只剩机理推断（E4），就是虚报。此处最易漏，因为摘要不重读、结论不回头。

**核验等级必须写进数字来源表**（第 0 步），不许只在心里记。写"量级"却在正文给区间端点，属自相矛盾，逐条核对时必被抓。

## 二、执行顺序（不得跳步）

```
0 禁令体检 → 1 定标 → 2 结构 → 3 论证 → 4 证据与引用 → 5 表述 → 6 格式 → 7 机械核验 → 8 交付记录
```

顺序有理由：禁令不过，改得再好也要重来；结构不过，改措辞是白费；论证不过，改格式是粉饰；证据不过，一切结论无效。

### 0　禁令体检（动笔第一件事）

先对原稿扫禁令 1 与禁令 2，把命中处连位置一起列出来，不要只写"已检查"。

```bash
python scripts/audit_manuscript.py <稿件.docx>   # 只看 F5 / F6 / R7 三行即可
```

再列禁令 4 的底账：把全稿每一个数字（含量、倍率、温度、时间、粒径、强度、标准限值）抓出来，逐个标注来源类别与证据等级，写成一张表：

| 数字 | 所在位置 | 来源类别 | 公开出处 | 证据等级 | 正文现写法 |
|---|---|---|---|---|---|
| 甲 | 2.1 某参数 | 公开文献 | `[@某键]` p.页码 | E1 | 区间写法 ✓ |
| 乙 | 2.2 某性能 | 填表时空 | 待回溯 | — | 精确值 ✗ |
| 丙 | 表 1 | 公开文献（综述） | `[@某键]` | E2 | 区间端点 ✗ 应改"约…量级" |

来源类别只有四种：**公开文献 / 现行标准 / 教学材料 / 无来源**。后两种一律不得留在稿件里，按禁令 4 的三步处理（回溯 → 降级 → 删除）。

证据等级按铁律 5 的四级填（E1 逐字 / E2 量级 / E3 可复算 / E4 定性）。**末列"正文现写法"必须与等级相符**：E2 却写了区间端点、E4 却写了具体数值，都是虚报，改法与改等级二选一，不得两边都留。这张表须在交付记录里留档，便于逐条复核。

这一步是必选项：改稿过程中极易自己引入禁词（补一句来源说明就写进"课件"）和新破折号（加一处解释就打"——"），也极易把教学材料里的数字当文献值搬进来，且往往发生在"改进"的名义下。**基线为 0，交付前再扫一次，两次都为 0 才继续。**

### 1　定标（先确认，不动笔）

必须确认四项，缺一项就问，不要假定：

1. **字数口径**：汉字数 / Word"字数" / 字符数。三者差可达 30%，报数必须写明是哪一个。
2. **字数上下限**：只有下限还是有上限；上限从哪来。
3. **格式依据**：任务方标准 / 机构格式文件（S 层，须取到原件）/ 期刊模板。**不得用"一般机构都这样"代替文件。**
4. **改动边界**：可否增删章节、可否改数据、可否换文献。

产出一句话的验收标准，形如：`正文汉字数不少于下限、无上限；格式按任务方标准加机构格式文件；不得改动数据与已核实文献。`

### 2–6　五类体检

按 `references/diagnosis.md` 执行，每类只看**该类致命项 + 可执行项**，不做无差别罗列（用户明确反对"广撒网"）。

高频致命项，按优先级：

| 优先级 | 缺陷 | 为什么致命 |
|---|---|---|
| 1 | 摘要宣告的创新点，正文无论证段落 | A8"独立见解"落空，一切措辞问题都次要 |
| 2 | 引言提出的问题，结论未回答 | 论证链断裂 |
| 3 | 同一性质在不同章节评价相反 | 逻辑自相矛盾 |
| 4 | 结论写成编号条目 | 论文按连贯论述写，不落报告或幻灯片条目（C2-1） |
| 5 | 引证错配、数据无出处 | 等同编造（B 层引文规范） |
| 6 | 判据无物理含义、取样含定义域外点 | 方法不可执行（C2-7、C2-9） |

### 7　机械核验

```bash
python scripts/audit_manuscript.py <稿件.docx> --count hanzi --min-refs 25 --min-chars 3000 --json audit.json
```

`--min-refs` 与 `--min-chars` 由任务方给定，示例值仅为脚本默认；下限来源不明时先问，不要照抄默认值当作要求。

**逐处改稿时加 `--brief`**：只打一行（FAIL／WARN 计数、汉字数、告警代码），改一句跑一次。

```bash
python scripts/audit_manuscript.py <稿件.docx> --brief
# 例：某稿.docx：FAIL 0／WARN 1｜汉字 8807｜S2
```

只在交付前跑一遍完整核验，等于把发现问题的时间点推到已经无法回头的时候；而局部改写最容易引入的恰恰是旧稿里没有的违规（把一句陈述改成「调节的是甲而非乙」就触发对偶否定，补一句来源就可能写进破折号）。简式模式让这一步的成本低于最后集中排错，也就没有理由跳过。

检查项：**禁令 1 禁词与禁令 2 破折号**、字数口径、参考文献条数与编号连续性、顺序编码制是否被破坏、未被引用条目、摘要/关键词、**摘要体裁**（A1 免责声明、A2 来源交代、A3 引注标记、A4 图表指引、A5 英文免责）、风险表述（教学口吻、应试语、无出处断言、绝对化）、**元话语**（交代写作安排、代替读者判断、模糊回指）、数字与单位格式（`~`→`～`、℃ 空格、连接号选型）、条目化程度、图表编号。

禁令两条为 FAIL 且不可豁免：`F5 禁词` 与 `F6 破折号`。交付前必须为 0；若稿件引用他人原文而含破折号，改写该引文或改为转述，不得原样保留。

`R7 文献表含教学材料` 亦为 FAIL：参考文献条目中出现"课件""讲义""教案""幻灯片""课堂教学""习题"等字样即触发，须删除该条并把引用处改为公开文献或降级表述。

`W2 元话语` 为 WARN，分四类：交代写作安排（"值得展开""留待某节讨论""下面将""本节先"）、宣告写作决策（"本文认为""本文选择"）、代替读者判断（"不难看出""由此可见""显然"）、模糊回指（"如前所述""上文所述"）。

这类句子的共同点是把论述变成对写作过程的叙述：读者读到的是作者打算写什么、作者觉得什么重要，而不是研究内容本身。改法有三条：铺垫语（"值得展开""有三条思路"）整句删去，直接从内容起句；"留待某节讨论"改为具体节号引用，或就把该内容写在此处；"不难看出""显然"删去后回读一遍，若删了读者跟不上，说明缺的是一步推导，补推导而非补断言。

本条单列的理由：这类表述不含禁令词、不是破折号、不构成对偶否定、也不是条目化，前几组检查一组都不会命中。它是论文体与非论文体的分界，靠词表查不出来就等于没有约束。

`A1–A5 摘要体裁` 为 WARN，只扫摘要区（中文与英文各一段，止于关键词行），不扫正文：

| 码 | 类别 | 典型写法 | 处理 |
|---|---|---|---|
| `A1` | 免责声明 | "未开展实验""仅为机理推断""尚待中试验证" | 移入引言，与数据来源合并成一处交代 |
| `A2` | 来源交代 | "数据均取自公开文献与现行标准" | 同上 |
| `A3` | 引注标记 | "见文献[3]""[@键名]" | 摘要不带引注，删标记，正文对应处标注 |
| `A4` | 图表指引 | "见表 1""如图 2" | 摘要不自引图表编号，改为文字概括 |
| `A5` | 英文免责 | "no new experiments were performed""all data are taken from…" | 与 `A1` 同处处理，中英文须同步 |

**摘要只写问题、方法、结果、结论**。研究边界与证据等级是方法学交代：读者要先看到论证，限定条件才有落点；写进摘要，等于在读者读到论证之前先替自己降级，也把一篇以文献综合与机理推演为主的稿件提前说成二手材料。这不是措辞轻重问题，是位置问题。对后续工作的展望（"进一步研究尚需开展"）属摘要常规内容，不在此列，检测器也已排除。

来源交代与免责声明在全稿**只写一处**，通常落在引言提出问题之后、进入正文之前；摘要、结论各自复述一遍，三处措辞还会互相漂移，正是铁律 5"回扫三处"要盯的地方。

规范状态两项（铁律 5 的配套，规则可判定）：

| 项 | 判定 | 处理 |
|---|---|---|
| `B1 编号引用缺发布年` | 正文出现规范主编号而无发布年份 | 补年份；同一规范全文写法统一 |
| `B2 草案当现行` | 同一句的草案词（征求意见稿／修订计划／报批稿／草案）后 24 字内出现"规定为／限值为／应不大于" | 改为"修订计划拟…"，不得与现势动词同句 |
| `B3 实测类措辞无引注` | 句含"实测／测定为／实验表明"但无引注、无公式号 | 本文实测给方法与数据；引自文献补引注；仅推断改"机理上应" |

`B1` 为 FAIL，`B2`、`B3` 为 WARN 且必须人工复核：`B2` 只查同句共现，**规范状态是否真的现行仍须查发布机构平台**；`B3` 查不出"引注挂错"（有引注但引文不含该值，属语义判断）。修改单无法机械识别，须人工确认后写入"含修改单"字样。

- 写作稿（含 `[@键名]` 占位）会提示"源文件模式"，须对构建后的 `.docx` 复跑。
- 脚本只做规则可判定项，**语义判断由模型负责**，不得用脚本通过代替论证审查。
- 退出码 1 表示存在 FAIL，交付前必须清零或在说明中逐条解释。

### 8　交付记录

产出《改进说明》，与稿件一并交付，含：改动清单（五行对照）、**数字来源表**（每个数值的来源类别、公开出处、证据等级与正文现写法，见第 0 步）、明确放弃项及理由、核验结果（字数口径与数值、文献条数、FAIL/WARN 清单）。改动用 git 提交，提交信息写清依据编号。

**数字来源表的末两列必须自查一遍**：E2 不得配区间端点，E4 不得配具体数值，E3 不得挂引注。这三条是铁律 5 的落地点，也是交付后最容易被逐条核对抓住的地方。凡本轮做过降级（删数据、改定性）的，另在《改进说明》中列出"回扫三处"的结果：摘要、引言、结论各改了什么，没有对应提法的写明"无"。

**交付前最后一道**：对最终 `.docx` 复扫禁令 1、2、6，含表格单元格与题注。源文件干净而 docx 里出现禁词，说明构建脚本或表体里混入了，须一并清。记录里写明"禁词 0 处、破折号 0 处"。

**版本控制纪律（禁令 5，见第零节）**：提交前先 `git status --short` 逐行过一眼，再 `git add <明确路径>`。禁止 `git add -A` 与 `git add .`。交付目录里恒有三类东西不该入库：目检用的渲染件与页面截图、`*.bak_*` 草稿备份（版本历史已由 git 承担）、以及作为来源被否的教学材料。仓库须带 `.gitignore` 与 `pre-commit` 拦截，机制见 `references/repo-hygiene.md`。

## 三、常用判断（易错处）

| 情形 | 正确做法 |
|---|---|
| 某个数字只在自己手头的教学材料里见过 | 按禁令 4 走三步：回溯公开文献 → 降级为定性 → 删除。不得直接写入，不得改挂未核实的文献，不得改单位使其"像文献值" |
| 删掉了数据，但摘要/结论里那句结论还在 | 按铁律 5 回扫三处（摘要、引言、结论）。正文证据降到 E4 而摘要仍写"实测""经验规律"，属虚报，必须同步降级 |
| 只看到综述里的量级，想写成精确区间 | 那是 E2 撑 E1 写法。要么取到原文升 E1，要么保留"约…量级"不写端点 |
| 数字是自己按公式算的 | E3，必须给算式与公式编号，正文写"按式（n）估算"，不得写成"实测"或挂引注 |
| 要写"现行规范" | 先查发布机构平台的状态，再查有无修改单。有修改单须注明"含第 N 号修改单"，否则读者会按原版理解 |
| 用户说"还在犯错""你听什么了" | 先别解释。立刻全稿扫禁令 1 与禁令 2，报命中数与位置；是复发就直接改到 0，并说明是什么时候引入的 |
| 要指代材料来源 | 写"文献""公开报道"，或省去来源；**不得写"课件""讲义""课堂""本课"**，也不得为避开禁词而编出处 |
| 需要解释、举例、转折 | 用冒号、分号、逗号、句号，**不用破折号**；改后复读，检查有无"：：""。，"残留 |
| 用户说"字数超了" | 先问口径与上限来历，不要直接删内容 |
| 分点太多 | 分清"内容是否必要"与"该不该写成要点"，后者是文体问题，论文的结论、机理、工艺比较都应是连贯论述 |
| 要提"改进思路" | 必须给工序、参数窗口、判据、代价，不能写"应加强研发" |
| 摘要写了"本文提出" | 正文必须有对应论证段，结论必须有收口（C2-5 三点闭合） |
| 找不到文献支撑某句 | 删句或降级表述，不得用"已有研究表明"顶替引注 |
| 任务方给的格式要求与标准冲突 | 以任务方要求为准，同时说明标准差异 |
| 涉及实验、医疗、化学安全 | 只做文献与机理层面的分析，注明未做实验，不把模拟当实验结论 |
| 要提交代码或稿件 | 先 `git status --short` 通看，再 `git add <明确路径>`；**不用 `git add -A`**。提交后 `git show --stat` 数一遍文件 |
| 用户说"仓库一片混乱" | 先查根因（哪个提交带进了什么、`.gitignore` 够不够），再清；只删当次垃圾不改机制，必然复发。流程见 `repo-hygiene.md` |
| 要删 `.bak` 备份 | 先抽验 `git show <提交>:<文件>` 能取回，再删；删后告知恢复命令 |
